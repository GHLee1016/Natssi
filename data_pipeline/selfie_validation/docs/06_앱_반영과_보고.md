# 06. 앱 반영과 결과 보고

## 앱에 넣을 곳 (저장소 GHLee1016/Natssi)
| 무엇 | 파일 | 지금 | 바꿀 것 |
|---|---|---|---|
| MDC95 | `backend/app/config.py` | `MDC95_A_STAR = 1.8` (예시값) | 실측값, 주석에 "팀원 n명·세션 k·측정일" |
| 품질 검사 | `backend/app/quality.py` `check(image_bytes)` | 밝기·해상도만, 고개 각도·표정은 "준비 중" | 확정한 항목 추가 |
| 측정 | (없음) | 붉은기는 가상값 | `measure_redness.py`의 ROI·a\* 계산을 옮김 |
| 화면 문구 | `frontend/src/pages/Capture.jsx` 안내문 | "밝기와 해상도만 확인해요" | 실제 검사 항목에 맞게 |
| 기기 변경 | 판정 엔진·기록 | 기기 정보 없음 | 촬영 기기를 기록하고, 바뀌면 평소 범위를 새로 만듦(그동안 '구분 불가'). 근거: docs/07 |
| 처리방침 | `frontend/src/pages/Legal.jsx` 사진 처리 안내 | "붉은기 측정은 아직 연결되지 않았어요" | 측정을 연결하면 문구를 바꾸고 다시 동의받는 절차 확인 |

`quality.check()`가 돌려주는 형식은 그대로 유지한다(프런트가 이 형식을 씀):
```
{"passed": bool, "checks": [{"name": "해상도", "ok": bool|None, "detail": "...", "implemented": bool}, ...],
 "message": "...", "redness": float|None, "note": "..."}
```
- 사진은 저장하지 않는 원칙을 유지한다(검사 후 폐기).
- Vercel 서버리스 함수 크기 제한 때문에 MediaPipe를 서버에 올리기 어려울 수 있다. 그 경우 대안: (1) 브라우저에서 MediaPipe Tasks(JS)로 랜드마크·자세·표정을 검사하고 숫자만 서버로 보냄, (2) 측정 서버를 따로 둠. 본선까지는 **MDC95 값 교체와 검사 기준 문서화**가 우선이고, 측정 연결은 시간이 되면 한다.

## 발표·멘토링용 한 장 요약 양식
```
반복 촬영 신뢰도 (예비 검증)
- 대상: 팀원 n명, 사람당 k일 × 하루 r장, 같은 폰·같은 장소, 색 보정 없음
- 측정: 양 볼 a*(CIELAB) 중앙값, 품질 검사 통과 사진 m/M장
- 결과: MDC95(하루 1장) = x.xx (95% CI a~b) → 앱 판정의 최소 변화 폭으로 적용
        ICC(A,1) = 0.xx (CI a~b, 대상자가 적어 참고용)
- 품질 검사 효과: 전체 사진 MDC95 y.yy → 통과 사진 x.xx
- 한계: 대상자 수가 적고 피부색 범위가 좁음, 한 기종·한 장소 결과, 다른 환경은 추가 검증 필요
```
- 결과 문장에 진단·효능 표현을 쓰지 않는다. "측정 오차를 넘는 변화만 신호로 표시한다"처럼 쓴다.
- 숫자는 `results.json`에서 그대로 옮긴다(반올림 규칙: 소수 둘째 자리).
