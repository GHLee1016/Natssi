# 01. 배경과 목표

## 낯씨에서 측정값이 쓰이는 곳
- 앱은 사용자의 기록마다 **볼 붉은기 a\***(CIELAB, 양 볼 평균)를 쓴다.
- 판정 엔진(`backend/app/judge.py`)의 평소 범위: **중앙값 ± max(MDC95, 3 × 1.4826 × MAD)** (같은 루틴 버전, 기록 7개 이상)
  - MDC95는 "다시 찍기만 해도 생기는 흔들림"의 상한이다. 이보다 작은 변화는 측정 오차와 구분할 수 없으므로 평소 범위의 **최소 폭**으로 쓴다.
  - 지금 `MDC95_A_STAR = 1.8`은 **예시값**이다. 이 프로젝트에서 실측값으로 바꾼다.
- 판정 4단계: 신호 없음 / 관찰 중 / 신호 있음 / 구분 불가(품질 미달·기록 부족)
- 사진 품질 검사(`backend/app/quality.py`)는 지금 밝기·해상도만 실제로 하고, 고개 각도·표정은 "준비 중"이다. 이 프로젝트의 검사 코드를 앱에 옮긴다.

## 기획서에서 약속한 것
- 반복 촬영으로 측정 신뢰도(ICC·MDC)를 확인한다(기획서에는 10명 이상으로 적혀 있음).
- 피부톤(밝기) 측정은 보정 없이 어렵다는 최신 연구를 근거로, 낯씨는 **색 보정 없이** 같은 장소·조명에서 반복 촬영하는 방식으로 정확도를 확보하고, 붉은기·트러블처럼 상대 변화 위주로 본다.
- 따라서 이 검증은 "보정 없이 같은 환경에서 반복 촬영했을 때 a\*가 얼마나 안정적인가"를 보여주는 것이 핵심이다.

## 이번 검증의 산출물
1. `measurements.csv` — 사진별 품질 검사 결과와 a\* (사진 없음, 숫자만)
2. `results/report.md`, `results.json` — ICC, SEM, MDC95와 95% 신뢰구간, 품질 검사 전후 비교
3. 품질 기준 점검표(`docs/05` 양식) — 기준별로 나쁜 사진을 잘 걸렀는지
4. 앱 반영안 — `MDC95_A_STAR` 새 값, `quality.py`에 옮길 검사 항목과 기준값
5. 발표·멘토링용 한 장 요약 — 무엇을 확인했고 한계는 무엇인지
