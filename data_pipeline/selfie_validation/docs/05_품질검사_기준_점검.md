# 05. 품질 검사 기준 점검

목표: 품질 검사가 "측정이 흔들리는 사진"을 잘 거르고, 좋은 사진은 덜 버리는가.

## 방법 1: 사람 눈 판정과 비교
1. 사진마다 팀원 1명이 보고 `good / bad` + 이유(흐림, 고개 돌아감, 웃음, 그림자, 날아감 등)를 `labels.csv`에 적는다(열: file, human_label, human_reason). 판정하는 사람은 자동 검사 결과를 보기 전에 적는다.
2. 자동 검사(`quality_pass`, `flags`)와 비교해 표를 만든다.

|  | 사람: good | 사람: bad |
|---|---|---|
| 자동: 통과 | 맞음 | **놓침** |
| 자동: 탈락 | **과잉 탈락** | 맞음 |

3. 항목별로 놓침·과잉 탈락 사례를 몇 장씩 보고(사진은 팀원 컴퓨터에서) 기준값을 조정한다.

## 방법 2: 측정 오차로 판단 (사진을 안 봐도 됨)
- 같은 세션 사진들의 중앙값에서 얼마나 벗어났는지(|a\* − 세션 중앙값|)를 사진마다 구한다.
- 항목별로 걸린 사진과 안 걸린 사진의 벗어남 크기를 비교한다. 걸린 쪽이 확실히 크면 그 항목은 의미가 있다.
- 기준값을 바꿔 가며(예: yaw 8°/10°/15°) "통과율"과 "통과 사진의 MDC95"를 같이 표로 본다. 통과율이 너무 낮아지면(예: 70% 미만) 실사용에서 사용자가 너무 자주 다시 찍어야 하므로 균형을 잡는다.

## 기록 양식 (기준을 바꿀 때마다 한 줄)
| 날짜 | 항목 | 이전 기준 | 새 기준 | 이유 | 통과율 전→후 | MDC95 전→후 |
|---|---|---|---|---|---|---|
| | | | | | | |

## 주의
- 결과가 좋아 보이게 하려고 기준을 계속 바꾸지 않는다. 바꾼 횟수와 이유를 모두 남긴다.
- 확정한 기준값은 `docs/06`에 따라 앱 `quality.py`로 옮긴다.
