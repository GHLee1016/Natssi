# 03. 붉은기 측정 방법 (code/measure_redness.py)

## 순서
1. 사진 읽기: EXIF 회전 반영 → RGB
2. 얼굴 랜드마크: MediaPipe Face Landmarker(478점 + 표정 점수 + 머리 자세 행렬)
3. 품질 검사(아래 표). 하나라도 걸리면 `quality_pass=False`, 이유는 `flags`에 쉼표로 남긴다. **측정값은 그래도 계산해 둔다**(품질 검사 효과를 비교하려고).
4. 볼 영역(ROI): 랜드마크 다각형 2개(사진 기준 왼쪽 `CHEEK_IMG_LEFT`, 오른쪽 `CHEEK_IMG_RIGHT`)
5. 색 변환: sRGB → 선형 → XYZ(D65) → CIELAB. 하얗게 날아간 픽셀(어느 채널이든 ≥250)과 아주 어두운 픽셀(최댓값 <20)은 뺀다.
6. 볼마다 a\*의 **중앙값**(점·모공 그림자에 덜 흔들림), 두 볼 평균 = `a_star`. 참고로 L\*, b\*, 평균값도 남긴다.

## 품질 검사 기준 (처음 값 — docs/05 절차로 점검 후 확정)
| 항목 | 기준 | flags 이름 | 앱과의 관계 |
|---|---|---|---|
| 해상도 | 짧은 변 ≥ 480px | resolution | 앱과 같음 |
| 밝기 | 전체 평균 70~210 | brightness | 앱과 같음 |
| 얼굴 | 1명만 검출 | no_face, multiple_faces | 새로 추가 |
| 얼굴 크기 | 얼굴 폭 ≥ 사진 폭의 25% | face_small | 새로 추가 |
| 흐림 | 얼굴 영역 라플라시안 분산 ≥ 60 (256px로 맞춘 뒤) | blur | 새로 추가 |
| 고개 각도 | yaw ≤ ±10°, pitch ≤ ±10°, roll ≤ ±8° | head_pose | 앱의 "준비 중" 항목 |
| 표정 | 미소 ≤ 0.40, 눈 감음 ≤ 0.50 (블렌드셰이프) | smile, eyes_closed | 앱의 "준비 중" 항목 |
| 노출 날아감 | 볼 영역에서 ≥250 픽셀 ≤ 1% | clipped_L/R | 새로 추가 |
| 볼 영역 크기 | 볼마다 유효 픽셀 ≥ 400 | roi_small_L/R | 새로 추가 |

## 처음에 꼭 확인할 것 (아직 검증 안 된 부분)
- **MediaPipe 부분은 작성 환경에서 모델을 받을 수 없어 실제 얼굴로 돌려보지 못했다.** 첫 실행은 사진 5장 정도로 `--debug-dir`를 켜고, 다각형이 양 볼 위(코 옆~광대 아래, 입가·콧방울·눈밑 그림자 제외)에 있는지 눈으로 확인한다. 어긋나면 랜드마크 번호를 고친다.
- 머리 자세(yaw/pitch/roll)의 부호와 축은 고개를 일부러 돌린 사진 몇 장으로 확인한다(예: 오른쪽으로 돌렸을 때 yaw가 커지는지). 축이 다르면 `euler_from_matrix`를 고친다.
- 흐림 기준 60은 첫 값이다. 흔들린 사진 몇 장과 또렷한 사진으로 분포를 보고 정한다.

## 이미 확인한 것
- 색 변환: 흰색(L=100, a=0, b=0), sRGB 빨강(L≈53.2, a≈80.1, b≈67.2) 기준값과 일치.
- 가상 페르소나 얼굴 A/B/C(같은 얼굴에 볼 붉은기만 다르게 만든 이미지)에서 볼 사각형을 손으로 잡아 측정: A ≈ 14.2, B ≈ 19~22, C ≈ 15 → 붉은기를 더한 쪽이 a\*가 커짐(방향 정상).
- 같은 사진에서 왼쪽 볼 L\*≈79, 오른쪽 볼 L\*≈60으로 **조명이 한쪽으로 치우치면 두 볼 밝기가 크게 다르다.** a\*는 비슷했지만, 반복 촬영에서 조명 방향이 바뀌면 오차가 커질 수 있다 → 촬영 장소·조명 고정이 중요하고, 분석 때 볼별 값(a_L, a_R)과 L\* 차이도 함께 본다.

## 하지 않는 것
- 색 보정(컬러 체커, 화이트밸런스 보정) — 기획서 방침대로 보정 없이 반복 촬영의 일관성으로 간다. 결과가 너무 흔들리면 그때 "보정 필요"로 보고한다.
- 피부톤(L\*)으로 판정하지 않는다. L\*는 품질·조명 확인용 참고값이다.
